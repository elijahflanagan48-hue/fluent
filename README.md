# fluent. — личная студия английского

Рабочий адрес: **https://fluent-studio.onrender.com/**. Хостинг — Render Free, база и приватные вложения — отдельный проект Supabase Free `fluent`. Первое создание кабинета владельца требует секретного кода из Render Environment; не публикуйте его в GitHub или сообщениях.

Веб-приложение преподавателя и учеников. Исходники хранятся в GitHub. Локально используется SQLite; бесплатный облачный вариант — Render Free + отдельный Supabase Free (Postgres и приватные вложения). Словарь не включён.

## Готовые сценарии

- Вход по email и паролю; приглашение ученика с одноразовой ссылкой, восстановление доступа и смена пароля. Роли проверяются сервером: ученик получает только свои данные.
- Календарь на неделю и месяц, повторяющиеся уроки, свободные окна, запись и перенос. Проверка пересечений времени, часовые пояса и переходы на летнее время.
- Правила отмены: настраиваемый срок, явное подтверждение списания при поздней отмене. Занятие списывается после отметки преподавателя о проведении.
- Пакеты занятий, ручная оплата по вашей ссылке или QR СБП, история начислений и списаний. Кнопка ученика «Я оплатил» создаёт отметку, а занятия начисляются только после вашего подтверждения.
- Вложение чека, комментарий о ненайденном платеже, исправление ошибочной отметки без имитации банковского возврата. Перенос начального баланса и корректировки с указанием причины.
- Домашние задания с текстовыми ответами, файлами и голосовыми записями до 3 минут. Проверка, оценка, комментарии и возврат на доработку. Повторно используемые шаблоны.
- Общая и персональная библиотека материалов, цели, измеримый прогресс и оценки навыков.
- Личные сообщения, внутренние уведомления, поиск по разделам, ученикам и заданиям.
- Персональные ежемесячные отчёты: черновик, комментарий, публикация ученику, печать и сохранение в PDF через браузер.
- Аналитика фактических поступлений, уроков, выполнения домашних заданий и загрузки опубликованного расписания.
- Реферальные коды. Преподаватель включает программу и задаёт бонус; он начисляется за первую подтверждённую оплату приглашённого ученика.
- CSV-экспорт, ручные резервные копии и ежедневные автоматические архивы базы и вложений с хранением последних семи копий.
- Адаптация к телефону и компьютеру, управление с клавиатуры и быстрый поиск `⌘/Ctrl K`.

## Быстро посмотреть

Для локального просмотра достаточно Python 3.9+ (в рабочем Docker используется Python 3.12):

```sh
python3 -B run.py --demo
```

Откройте `http://127.0.0.1:4174`. На странице входа есть кнопки тестовых ролей. Данные демонстрации сохраняются в `data-demo/` и не смешиваются с рабочей базой. Выйдите из кабинета для проверки другой роли. Это локальный режим; не публикуйте его наружу.

## Локальная рабочая студия

Скопируйте `.env.example` в `.env`, затем:

```sh
python3 -B manage.py owner --email you@example.com --name "Ваше имя"
python3 -B run.py
```

Пароль вводится скрыто в терминале. Рабочие данные появятся в `data/`. На чистой базе нет вымышленных учеников, пакетов или оплат.

После входа:

1. В настройках вставьте ссылку СБП и загрузите QR-код PNG/JPEG/WebP.
2. Создайте ваши пакеты и цены. При необходимости задайте индивидуальную платёжную ссылку для пакета.
3. Добавьте учеников и передайте каждому личную ссылку приглашения. Само создание приглашения не отправляет email.
4. В карточках перенесите уже оплаченные занятия через «Корректировать баланс».
5. Добавьте уроки, правила отмены и задания.

Ученик открывает реквизиты, переводит нужную сумму через приложение банка и нажимает «Я оплатил». Приложение не обращается к банку и не получает банковские ключи. Преподаватель проверяет поступление в Т-Банке и подтверждает отметку в кабинете. Повторное подтверждение не начисляет занятия дважды.

## Размещение для учеников

### Бесплатный запуск: Render Free + Supabase Free

В `render.yaml` указан только `plan: free`, без платного диска и без временной Render Postgres. Временная папка сервера используется исключительно для технических файлов. База и вложения должны находиться в отдельном Supabase Free проекте; существующие проекты не изменяются.

1. Проверьте, что организация Supabase и пространство Render используют Free/Hobby, без платных дополнений. На Render учтите общие с другими приложениями часы, трафик и сборки. До запуска проверьте отсутствие платных перерасходов в Billing; бесплатный сервер сам по себе не ограничивает все расходы аккаунта.
2. Для нового проекта получите административную SQL-схему: `python3 -B manage.py cloud-schema`. Примените её администратором. Таблицы создаются в приватной схеме `fluent` с RLS, без доступа из Data API. Задайте отдельному `fluent_runtime` пароль и разрешите LOGIN через защищённую административную сессию. Он получает только CRUD таблиц приложения, не права владельца базы. Никогда не публикуйте пароль.
3. Создайте приватный bucket `fluent-private` с ограничением файла 10 МБ, без публичных политик. В Render Environment задайте `DATABASE_URL` из Supabase Connect (IPv4 pooler, пользователь `fluent_runtime.<ref>`), `SUPABASE_URL` и серверный `SUPABASE_SECRET_KEY`. Ключ должен быть новым `sb_secret_…`, а не publishable/anon. Он не передаётся браузеру.
4. Используйте [Deploy to Render](https://render.com/deploy?repo=https://github.com/elijahflanagan48-hue/fluent) или создайте Web Service через подключённый аккаунт с теми же параметрами. Не выбирайте платные планы, диски или дополнительные базы.

После запуска Render выдаст HTTPS-адрес вида `https://имя.onrender.com`. Откройте его, скопируйте значение `FLUENT_SETUP_TOKEN` из раздела Environment в панели хостинга и создайте кабинет владельца в браузере. Эта операция доступна только с секретным кодом и только до создания первого преподавателя. Код нельзя публиковать или отправлять ученикам. Пароль вы задаёте непосредственно на сайте.

Переменная `FLUENT_BASE_URL` определяется автоматически по адресу Render; для собственного домена задайте её явно. Обновления из `main` запускаются после успешных проверок GitHub.

Бесплатные ограничения: Render засыпает после 15 минут простоя, пробуждение занимает примерно минуту. Напоминания, синхронизация и копии выполняются, когда сервис работает; точная доставка по времени не гарантируется, искусственные запросы для обхода сна не используются. SMTP-порты Free блокируются — почта требует отдельного HTTPS-провайдера; без него используйте Telegram и личные ссылки приглашений/сброса. Supabase может приостановить неактивный проект. Не включайте платные функции автоматически.

Для вложений приложение ограничивает суммарный объём 800 МБ, оставляя запас в бесплатном хранилище 1 ГБ. Ежедневные облачные архивы содержат базу (без активных сессий и ключей), не дублируют вложения и хранятся в приватном bucket, последние семь копий. Оригиналы вложений хранятся отдельно там же. Ручная полная копия включает файлы, но ограничена 128 МБ; скачивайте копии вне провайдера. Бесплатный Supabase не предоставляет автоматические резервные копии уровня платного плана.

### Собственный сервер

GitHub Pages обслуживает статические файлы и не запускает этот сервер. Репозиторий остаётся в GitHub, а приложение нужно разместить на VPS или другом хостинге с Python/Docker и постоянным диском.

Готовы `Dockerfile`, `compose.yaml` и пример HTTPS-прокси `deploy/Caddyfile`. На сервере:

1. Получите этот репозиторий, создайте `.env` из примера и задайте `FLUENT_BASE_URL=https://ваш-домен` без завершающего пути.
2. Запустите контейнеры:

```sh
docker compose up -d --build
docker compose exec app python manage.py owner --email you@example.com --name "Ваше имя"
```

3. Направьте домен на сервер и настройте Caddy или другой HTTPS-прокси на `127.0.0.1:8000`.

Контейнер `app` обслуживает кабинет, `worker` отправляет уведомления, обновляет подключённые календари и создаёт резервные копии. Оба используют один постоянный Docker volume `studio-data`. Не удаляйте volume при обновлениях. Production-вход требует HTTPS и запрещает демонстрационный режим.

Для обновления используйте `git pull` и `docker compose up -d --build`. Папки с данными и `.env` исключены из Git и Docker-образа.

## Дополнительные подключения

Эти адаптеры реализованы, но для работы требуют ваших учётных данных. Без них основные кабинеты, оплаты СБП, внутренняя переписка и уведомления продолжают работать.

### Telegram

Создайте своего бота через BotFather, заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и случайный `TELEGRAM_WEBHOOK_SECRET` в `.env`. После запуска на HTTPS:

```sh
docker compose exec app python manage.py telegram-webhook
```

В настройках пользователь нажимает «Подключить бота», переходит по персональной одноразовой ссылке и нажимает Start. Уведомления об уроках, сроках ДЗ, новых сообщениях и низком балансе отправляются только после подключения и при включённой подписке. Секрет webhook проверяется сервером. [Документация Telegram](https://core.telegram.org/bots/api#setwebhook).

### Email

Заполните параметры `SMTP_*`. Порт 465 использует TLS, 587 — STARTTLS. Пользователь включает уведомления в профиле. Письма восстановления доступа работают независимо от подписки на напоминания. Ключи почты не попадают в браузер.

### Google Calendar

В Google Cloud включите Calendar API и создайте OAuth client типа Web application. Укажите redirect URI `https://ваш-домен/api/integrations/google/callback`, задайте `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` на сервере. Каждый пользователь подключает собственный календарь в настройках.

Синхронизация односторонняя: из fluent. в основной Google-календарь. Создаются только события занятий этого пользователя; для преподавателя — вся студия. Изменения и отмены передаются фоновым процессом. Редактирование события в Google не переносит урок в fluent. Также доступен скачиваемый `.ics` без подключения. [Документация Calendar API](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert).

### Zoom

В Zoom создайте Server-to-Server OAuth app для своего аккаунта, разрешите создание, изменение и удаление встреч. Заполните `ZOOM_ACCOUNT_ID`, `ZOOM_CLIENT_ID`, `ZOOM_CLIENT_SECRET` и при необходимости `ZOOM_USER_ID`. В карточке урока появится создание встречи; переносы и отмены обновляются фоновым процессом. Ключ доступа ведущего ученикам не передаётся — только ссылка участника. Можно использовать готовую ссылку без API. [Документация Zoom](https://developers.zoom.us/docs/internal-apps/s2s-oauth/).

Живые подключения нельзя подтвердить без действующих ключей и аккаунтов. Реальные письма, встречи и уведомления при разработке не отправлялись.

## Резервные копии и восстановление

Архив можно создать из настроек преподавателя или командой:

```sh
python3 -B manage.py backup --output /путь/к/архиву.zip
python3 -B manage.py restore /путь/к/архиву.zip --destination /новая/пустая/папка
```

Для восстановления остановите приложение, восстановите в новую папку и задайте её через `FLUENT_DATA_DIR`. Не заменяйте работающую базу. Архив содержит базу и вложения, но исключает активные сессии, одноразовые ссылки и токены внешних подключений; после восстановления потребуется повторно подключить Google. `.env` сохраните отдельно. Храните скачанные архивы в своём защищённом месте.

Для восстановления пароля преподавателя с доступом к серверу:

```sh
python3 -B manage.py reset-owner --email you@example.com
```

## Проверка и устройство проекта

```sh
python3 -B -m unittest discover -s tests -v
node --check app.js
```

GitHub Actions запускает эти проверки на обновлениях и pull requests. Тесты используют временные базы, не обращаются к реальному банку и не отправляют сообщения.

- `index.html`, `app.js`, `styles.css` — браузерный интерфейс без сборки;
- `backend/schema.sql` — таблицы и ограничения;
- `backend/core.py`, `backend/service.py` — вход, правила, права доступа и операции;
- `backend/http.py` — WSGI API и защищённая выдача файлов;
- `backend/integrations.py`, `backend/jobs.py` — подключения, напоминания и очередь доставки;
- `manage.py`, `run.py`, `worker.py` — запуск, обслуживание и резервные копии;
- `deploy/`, `Dockerfile`, `compose.yaml` — размещение на сервере.

Проект рассчитан на одну студию преподавателя. Для нескольких независимых студий потребуется отдельная изоляция данных. Вложения ограничены 10 МБ на файл и 1 ГБ на пользователя. Записи и ключи не хранятся в GitHub; SQLite и вложения находятся на постоянном серверном диске.
# Перенос на Netlify Free

Новая серверная реализация находится в `serverless/`, точки входа — в
`netlify/functions/`. Это самостоятельный backend, не прокси к Render.
Python/SQLite-версия и существующая база Supabase сохранены для совместимости.

Netlify: команда сборки `node scripts/build-netlify.mjs`, публикуемая папка
`dist`, функции `netlify/functions`, Node.js 24. Только эти четыре публичных
файла попадают в `dist`; ключи, база и исходники сервера не публикуются.

В защищённых переменных **Functions / Production** нужны `DATABASE_URL`
(существующая ограниченная роль fluent_runtime), `SUPABASE_URL`,
`SUPABASE_BUCKET=fluent-private`, `SUPABASE_SECRET_KEY`, `FLUENT_SETUP_TOKEN`
и `FLUENT_BASE_URL` с новым HTTPS-адресом. Не передавайте секреты в GitHub,
build command, клиентский код или переменные с публичными префиксами.
Не выдавайте production-секреты предварительным сборкам чужих pull request.

Вход использует прежний формат паролей и серверных сессий. Вложения
передаются напрямую в закрытый Supabase по временной подписанной ссылке;
сервер проверяет владельца, размер, сигнатуру и тип файла перед публикацией
его в кабинете. Это сохраняет лимит вложений 10 МБ при ограничении Netlify
на размер HTTP-запроса. Скачивание тоже проверяет доступ и выдаёт ссылку
только на 60 секунд.

Фоновые задачи Netlify: напоминания и подключения каждые 15 минут,
резервная копия базы ежедневно в 02:30 UTC. Они расходуют бесплатную квоту
Netlify вместе с остальными проектами команды. Free не гарантирует
неограниченную нагрузку: при исчерпании месячного лимита сайты могут быть
приостановлены. Supabase Free также может приостановить проект при долгом
отсутствии активности. Отсутствие экрана запуска Render не означает
нулевую задержку любого API-запроса.

Проверки: `npm ci --ignore-scripts`, `npm test`, `npm run build`.
Для проверки Node API с настоящим Postgres в CI используется только
одноразовая локальная база `fluent_test`. Никогда не задавайте для тестов
адрес рабочей Supabase. Старый Render отключается только после успешной
проверки новой публикации и отдельного подтверждения переключения.
